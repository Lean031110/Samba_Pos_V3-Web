    25→    25→
    26→    26→```pseudo
    27→    27→# Source: Samba.Infrastructure/Settings/LocalSettings.cs:78
    28→    28→DECIMALS = 2                  # hardcoded; do NOT change without understanding the implications
    29→    29→
    30→    30→# Source: decimal.Round(value, n) in C# defaults to MidpointRounding.ToEven (banker's rounding)
    31→    31→# Source: decimal.Round(value, n, MidpointRounding.AwayFromZero) uses schoolbook rounding
    32→    32→# CRITICAL: SambaPOS mixes both modes — preserve exactly!
    33→    33→
    34→    34→function roundBankers(value, decimals = DECIMALS):
    35→    35→    # JS equivalent:
    36→    36→    # const f = Math.pow(10, decimals);
    37→    37→    # const n = value * f;
    38→    38→    # const isHalf = Math.abs(n % 1) === 0.5;
    39→    39→    # if (isHalf) return Math.sign(n) * Math.round(Math.abs(n) % 2 === 0 ? Math.floor(Math.abs(n)) : Math.ceil(Math.abs(n))) / f;
    40→    40→    # return Math.round(n) / f;
    41→    41→    # OR: use decimal.js with Decimal.ROUND_HALF_EVEN
    42→    42→    return Decimal.round(value, decimals, ROUND_HALF_EVEN)
    43→    43→
    44→    44→function roundAway(value, decimals = DECIMALS):
    45→    45→    # JS equivalent: Math.sign(value) * Math.round(Math.abs(value) * Math.pow(10, decimals)) / Math.pow(10, decimals)
    46→    46→    # OR: decimal.js with Decimal.ROUND_HALF_UP
    47→    47→    return Decimal.round(value, decimals, ROUND_HALF_UP)   # HALF_UP matches AwayFromZero for positives
    48→    48→
    49→    49→# Auto-contrast foreground (used by FlexButton and table tiles)
    50→    50→function pickForeground(hexColor):
    51→    51→    r = parseHex(hexColor, 0, 2)
    52→    52→    g = parseHex(hexColor, 2, 2)
    53→    53→    b = parseHex(hexColor, 4, 2)
    54→    54→    luma = 0.2126 * r + 0.7152 * g + 0.0722 * b
    55→    55→    return luma < 128 ? '#FFFFFF' : '#000000'
    56→    56→```

    60→    60→## 1. Ticket Lifecycle State Machine
    61→    61→
    62→    62→**Source:** `Ticket.cs` (no formal state machine; encoded as `(IsClosed, IsLocked)` booleans + JSON `TicketStates`).
    63→    63→
    64→    64→```
    65→    65→                                  ┌──────────────┐
    66→    66→                                  │     New      │  (Id=0, IsClosed=false, IsLocked=false)
    67→    67→                                  │ TicketBuilder│
    68→    68→                                  │   .Build()   │
    69→    69→                                  └──────┬───────┘
    70→    70→                                         │ Order added / Tag set / Entity linked
    71→    71→                                         ▼
    72→    72→                                  ┌──────────────┐
    73→    73→                                  │     Open     │  (Orders > 0, IsClosed=false, IsLocked=false)
    74→    74→                                  │   (Active)   │
    75→    75→                                  └──────┬───────┘
    76→    76→                                         │ CloseTicket() + LockTicket()
    77→    77→                       ┌─────────────────┘  OR  user clicks "Pay" then "Close"
    78→    78→                       ▼
    79→    79→                  ┌──────────┐
    80→    80→                  │  Locked  │  (IsLocked=true; Orders have Locked=true;
    81→    81→                  └────┬─────┘   adding items requires AddItemsToLockedTickets permission)
    82→    82→                       │
    83→    83→                       │ GetRemainingAmount() == 0
    84→    84→                       ▼
    85→    85→                  ┌──────────┐
    86→    86→                  │   Paid   │  (still IsClosed=false, but RemainingAmount=0)
    87→    87→                  └────┬─────┘
    88→    88→                       │ MarkTicketAsClosed action fires (typically on TicketClosing event)
    89→    89→                       │ Ticket.Close()  [Ticket.cs:79]
    90→    90→                       │   requires: RemainingAmount == 0 AND !HasActiveTimers()
    91→    91→                       ▼
    92→    92→                  ┌──────────┐
    93→    93→                  │  Closed  │  (IsClosed=true; PaidItems cleared;
    94→    94→                  └──────────┘   zero-amount AccountTransactions removed)
    95→    95→```

    97→    97→### Derived predicates
    98→    98→
    99→    99→```pseudo
   100→   100→function isTicketNew(ticket):    return ticket.Id == 0
   101→   101→function isTicketOpen(ticket):   return !ticket.IsClosed && !ticket.IsLocked && ticket.Orders.length > 0
   102→   102→function isTicketLocked(ticket): return ticket.IsLocked == true
   103→   103→function isTicketPaid(ticket):   return !ticket.IsClosed && ticket.GetRemainingAmount() == 0 && ticket.Payments.length > 0
   104→   104→function isTicketClosed(ticket): return ticket.IsClosed == true
   105→   105→```

   107→   107→### OrderState state machine (free-form JSON)
   108→   108→
   109→   109→States are stored as JSON in `Order.OrderStates` and named by convention. The built-in automation rules use `Status` as the group name:
   110→   110→
   111→   111→| State | Trigger | Effect |
   112→   112→|-------|---------|--------|
   113→   113→| New | OrderBuilder.Build() | Default |
   114→   114→| Submitted | OrderNumber assigned at CloseTicket | (implicit) |
   115→   115→| Void | `UpdateOrderState` action with `Status=Void` | `CalculatePrice=false` (excluded from totals) |
   116→   116→| Gift | `UpdateOrderState` action with `Status=Gift` | `CalculatePrice=false` + visual indicator |
   117→   117→| Cancelled | `UpdateOrderState` action with `Status=Cancelled` | Excluded from reports |

   223→   223→### WorkPeriod linking
   224→   224→
   225→   225→**IMPORTANT:** WorkPeriod is **NOT** a foreign key. The link is implicit via `Ticket.Date` falling within `[WorkPeriod.StartDate, WorkPeriod.EndDate]`. Reports filter on this date range. The "current work period" is held in memory by `IApplicationState.CurrentWorkPeriod`.
   226→   226→
   227→   227→### Department linking
   228→   228→
   229→   229→Set at `TicketBuilder.Build()` time: `ticket.DepartmentId = _department.Id`. The Department carries `WarehouseId`, `TicketTypeId`, `ScreenMenuId`, `PriceTag`, `TicketCreationMethod` — these are read at runtime via `_applicationState.CurrentDepartment`.
   230→   230→
   231→   231→### Table linking
   232→   232→
   233→   233→There is **no `Table` entity** in SambaPOS V3. Tables are `Entity` rows whose `EntityType.Name == "Tables"` (or similar). Linking happens via `Ticket.UpdateEntity(...)`:

   456→   456→## 4. CalculateTotals Algorithm (THE MASTER ALGORITHM)
   457→   457→
   458→   458→**Source:** `Ticket.GetSum()` at `Ticket.cs:308` and `Ticket.Recalculate()` at `Ticket.cs:656`. Every code path that mutates `Orders`, `Calculations`, or `Payments` ends with a call to `TicketService.RecalculateTicket` (`TicketService.cs:330`) which calls `Ticket.Recalculate()`.
   459→   459→
   460→   460→### 4.1 Order of operations (FINAL ANSWER)
   461→   461→
   462→   462→```
   463→   463→1. Sum ticket items           →  plainSum    = Σ order.GetTotal()              [Ticket.cs:413]
   464→   464→2. Apply pre-tax discounts    →  preTaxSvc   = CalculateServices(!IncludeTax)  [Ticket.cs:311]
   465→   465→                                (Calculations sorted by Order; DecreaseAmount makes negative)
   466→   466→3. Apply tax                  →  tax         = CalculateTax(plainSum, preTaxSvc) [Ticket.cs:348]
   467→   467→                                If TaxIncluded: tax already inside price (extracted, not added)
   468→   468→                                If !TaxIncluded: tax added on top
   469→   469→                                Rounding: per-line via TaxValue.Rounding (MidpointRounding.AwayFromZero)
   470→   470→                                Then rounded to 2 dp at ticket level (MidpointRounding.ToEven — banker's!)
   471→   471→4. Apply post-tax services    →  postTaxSvc  = CalculateServices(IncludeTax)   [Ticket.cs:314]
   472→   472→                                (applied to plainSum + preTaxSvc + tax)
   473→   473→5. Round                      →  decimal.Round(…, 2) at every step
   474→   474→                                Also: AccountTransaction.Amount rounded with MidpointRounding.AwayFromZero
   475→   475→                                                              [AccountTransaction.cs:203]
   476→   476→6. Set TotalAmount            →  TotalAmount = plainSum + preTaxSvc + tax + postTaxSvc
   477→   477→                                                              [Ticket.cs:688]
   478→   478→                                RemainingAmount = Round(GetSum() - GetPaymentAmount() + GetChangeAmount(), 2)
   479→   479→                                                              [Ticket.cs:436]
   480→   480→```

   657→   657→### 4.3 `computeCalculationAmount(calc, sum, currentSum)` — THE 5 calculation types
   658→   658→
   659→   659→```pseudo
   660→   660→# Source: Calculation.Update(sum, currentSum, decimals)  [Calculation.cs:22]
   661→   661→function computeCalculationAmount(calc, sum, currentSum):
   662→   662→    switch calc.CalculationType:
   663→   663→        case 0:
   664→   664→            # PERCENTAGE OF PLAIN SUM
   665→   665→            # Example: 10% discount on ticket total
   666→   666→            return calc.Amount > 0 ? (sum * calc.Amount) / 100 : 0
   667→   667→
   668→   668→        case 1:
   669→   669→            # PERCENTAGE OF RUNNING SUM (compounded — sees previous calc's effect)
   670→   670→            # Example: 10% service charge applied AFTER a discount was already subtracted
   671→   671→            return calc.Amount > 0 ? (currentSum * calc.Amount) / 100 : 0
   672→   672→
   673→   673→        case 3:
   674→   674→            # TARGET AMOUNT (final total should be exactly `Amount`)
   675→   675→            # Example: "Round to $50" by setting target
   676→   676→            if calc.Amount == currentSum:
   677→   677→                calc.Amount = 0
   678→   678→                return 0
   679→   679→            if currentSum > 0 and calc.DecreaseAmount and calc.Amount > currentSum:
   680→   680→                # Discount cannot exceed the current sum — zero it out
   681→   681→                calc.Amount = 0
   682→   682→                return 0
   683→   683→            if currentSum > 0 and (not calc.DecreaseAmount) and calc.Amount < currentSum:
   684→   684→                # Surcharge cannot be less than current sum — zero it out
   685→   685→                calc.Amount = 0
   686→   686→                return 0
   687→   687→            return calc.Amount - currentSum
   688→   688→
   689→   689→        case 4:
   690→   690→            # ROUNDING (to nearest multiple of `Amount`)
   691→   691→            # Example: round to nearest 0.05 (nickel rounding for cash)
   692→   692→            if calc.Amount > 0:
   693→   693→                # Round to nearest multiple (AwayFromZero for the .5 case)
   694→   694→                result = (roundAway(currentSum / calc.Amount, 0) * calc.Amount) - currentSum
   695→   695→            else:
   696→   696→                # Amount < 0: always round DOWN (truncate)
   697→   697→                result = (trunc(currentSum / calc.Amount) * calc.Amount) - currentSum
   698→   698→            if calc.DecreaseAmount and result > 0: result = 0
   699→   699→            if (not calc.DecreaseAmount) and result < 0: result = 0
   700→   700→            return result
   701→   701→
   702→   702→        case 2:
   703→   703→            # Unused — falls through to default
   704→   704→        case 5:
   705→   705→            # SCRIPTED — Amount is pre-computed by ExpressionService
   706→   706→            # before RecalculateTicket() is called.
   707→   707→            # Source: TicketService.cs:333-334
   708→   708→            #   calc.Amount = _expressionService.EvalCommand(
   709→   709→            #       "Calculation", "_" + calc.Name, {Ticket = ticket}, 0m)
   710→   710→        default:
   711→   711→            # FIXED AMOUNT (manual)
   712→   712→            return calc.Amount
   713→   713→```

   715→   715→### 4.4 `TaxValue.GetTax(...)` — THE tax formula
   716→   716→
   717→   717→```pseudo
   718→   718→# Source: TaxValue.cs:41-65
   719→   719→function TaxValue.GetTax(taxIncluded, price, totalRate):
   720→   720→    if taxIncluded and totalRate > 0:
   721→   721→        # Tax is INCLUDED in the price — extract it
   722→   722→        # totalRate = sum of ALL applicable tax rates on this order
   723→   723→        # (needed because the price includes all taxes, must distribute proportionally)
   724→   724→        if Rounding > 0:
   725→   725→            # Per-line rounding with MidpointRounding.AwayFromZero
   726→   726→            return roundAway((price * TaxRate) / (100 + totalRate), Rounding)
   727→   727→        else:
   728→   728→            # No per-line rounding — full precision kept
   729→   729→            return (price * TaxRate) / (100 + totalRate)
   730→   730→    elif TaxRate > 0:
   731→   731→        # Tax ADDED ON TOP of the price
   732→   732→        # (no per-line rounding — CalculationType=4 rounding happens at ticket level)
   733→   733→        return (price * TaxRate) / 100
   734→   734→    else:
   735→   735→        return 0
   736→   736→
   737→   737→function TaxValue.GetTaxAmount(taxIncluded, price, totalRate, plainSum, preTaxServices):
   738→   738→    # Source: TaxValue.cs:59-65
   739→   739→    if preTaxServices != 0:
   740→   740→        # Proportionally allocate pre-tax services to this order's taxable price
   741→   741→        price += (price * preTaxServices) / plainSum
   742→   742→    return GetTax(taxIncluded, price, totalRate)
   743→   743→```

  1792→  1792→## 14. Web-Clone Implementation Notes (CRITICAL)
  1793→  1793→
  1794→  1794→### 14.1 Rounding-mode inconsistency to PRESERVE
  1795→  1795→
  1796→  1796→SambaPOS V3 uses **two different rounding modes** depending on the code path:
  1797→  1797→
  1798→  1798→| Code path | Mode | Source |
  1799→  1799→|-----------|------|--------|
  1800→  1800→| `Ticket.CalculateTax` | `decimal.Round(value, 2)` (banker's / `MidpointRounding.ToEven`) | `Ticket.cs:350` |
  1801→  1801→| `Ticket.CalculateServices` | `decimal.Round(value, 2)` (banker's) | `Ticket.cs:376` |
  1802→  1802→| `Ticket.GetTaxTotal` | `decimal.Round(value, 2, MidpointRounding.AwayFromZero)` (schoolbook) | `Ticket.cs:694, 700` |
  1803→  1803→| `AccountTransaction.UpdateAmount` | `Decimal.Round(Amount, 2, MidpointRounding.AwayFromZero)` | `AccountTransaction.cs:203` |
  1804→  1804→| `TaxValue.GetTax` (when `Rounding > 0`) | `decimal.Round(..., Rounding, MidpointRounding.AwayFromZero)` | `TaxValue.cs:47` |
  1805→  1805→| `Calculation.Update` type 4 (rounding) | `decimal.Round(currentSum / Amount, MidpointRounding.AwayFromZero)` | `Calculation.cs:45` |
  1806→  1806→| `ProductTimerValue.GetPrice` | `decimal.Round(..., LocalSettings.Decimals)` (banker's) | `ProductTimerValue.cs:32` |
  1807→  1807→
  1808→  1808→**Web clone MUST preserve this inconsistency** for byte-perfect monetary parity. JavaScript `Math.round` rounds half-up (toward +∞ for `.5`), which matches `AwayFromZero` for positives but NOT for negatives.
  1809→  1809→
  1810→  1810→```javascript
  1811→  1811→// Use decimal.js with explicit rounding modes:
  1812→  1812→import Decimal from 'decimal.js';
  1813→  1813→Decimal.set({ precision: 28 });
  1814→  1814→
  1815→  1815→const roundBankers = (v, d = 2) => new Decimal(v).toDecimalPlaces(d, Decimal.ROUND_HALF_EVEN).toNumber();
  1816→  1816→const roundAway    = (v, d = 2) => new Decimal(v).toDecimalPlaces(d, Decimal.ROUND_HALF_UP).toNumber();
  1817→  1817→```
  1818→  1818→
  1819→  1819→### 14.2 `LocalSettings.Decimals = 2` is hardcoded
  1820→  1820→
  1821→  1821→`Samba.Infrastructure/Settings/LocalSettings.cs:78`. Expose as config but **default to 2** for parity.
  1822→  1822→
  1823→  1823→### 14.3 JSON-serialized fields with short DataMember names
  1824→  1824→
  1825→  1825→`Ticket.TicketTags`, `Ticket.TicketStates`, `Ticket.TicketLogs`, `Order.Taxes`, `Order.OrderTags`, `Order.OrderStates`, `Task.CustomData`, `Entity.CustomData`, `EntityStateValue.EntityStates`, `AccountScreen.AutomationCommandMapData`, `AppRule.RuleConstraints`, `AppAction.Parameter`, `Widget.Properties`, `ScreenMenuItem.OrderTags/OrderStates/AutomationCommand` are all JSON strings persisted in DB columns. The DataContract serializer uses **short `[DataMember(Name="XX")]` names** (e.g. `"TN"`, `"TV"`, `"TR"`, `"RN"`) for compactness.
  1826→  1826→
  1827→  1827→**Web clone must replicate the exact JSON wire format** if reading/writing existing `.sdf` files; otherwise can use full property names with a migration adapter.
  1828→  1828→
  1829→  1829→### 14.4 No formal state machine
  1830→  1830→
  1831→  1831→Do NOT model the Ticket lifecycle as a strict FSM. `(IsClosed, IsLocked)` plus the JSON `TicketStates` is what the code actually uses. Order states are even looser.
  1832→  1832→
  1833→  1833→### 14.5 Splitting = MoveOrders to targetTicketId=0
  1834→  1834→
  1835→  1835→There is no separate `SplitTicket` endpoint. The UI flow is `ExtractSelectedOrders` (handles partial-quantity cloning) → `MoveOrders`.
  1836→  1836→
  1837→  1837→### 14.6 Closing is two-phase
  1838→  1838→
  1839→  1839→1. `CloseTicket` saves and locks.
  1840→  1840→2. `MarkTicketAsClosed` (automation action) actually flips `IsClosed=true`.
  1841→  1841→
  1842→  1842→The port should preserve this separation OR unify it with a clear documented behavior. Recommended: **preserve the two-phase close** for behavioral parity (the user spec requires "logic-perfect" replication).
  1843→  1843→
  1844→  1844→### 14.7 PrintJob execution is async
  1845→  1845→
  1846→  1846→`AsyncPrintTask.Exec(highPriority, action, logService)` queues the print job. High-priority jobs (e.g. kitchen receipts on `OrderAdded`) run immediately; low-priority jobs are queued. **Web clone should use a similar priority queue** (e.g. `p-queue` with concurrency 1 + priority field).
  1847→  1847→
  1848→  1848→### 14.8 `AccountTransactionDocument` is the double-entry ledger
  1849→  1849→
  1850→  1850→Every monetary operation (sale, tax, discount, payment, change, refund) creates or updates an `AccountTransaction` inside the ticket's `TransactionDocument`. The port must replicate this — it is the audit trail and the source of truth for balances:
  1851→  1851→
  1852→  1852→```pseudo
  1853→  1853→# Source: AccountDao.GetAccountBalance
  1854→  1854→function GetAccountBalance(accountId):
  1855→  1855→    # = SUM(Debit - Credit) over all AccountTransactionValues with AccountId == accountId
  1856→  1856→    return db.AccountTransactionValues
  1857→  1857→        .Where(v => v.AccountId == accountId)
  1858→  1858→        .Sum(v => v.Debit - v.Credit)
  1859→  1859→```
  1860→  1860→
  1861→  1861→### 14.9 `Order.CalculatePrice = false` is how Gift orders are excluded
  1862→  1862→
  1863→  1863→Rather than being removed, Gift orders are kept in the ticket but excluded from totals via this flag. The port should support this flag on every order.
  1864→  1864→
  1865→  1865→### 14.10 Concurrency
  1866→  1866→
  1867→  1867→`TicketConcurrencyValidator` (`TicketDao.cs:146`) compares the in-memory ticket against the DB-loaded version on every `CloseTicket`. If `LastPaymentDate` differs (another terminal paid), the operation is rejected with `"TicketPaidLastChangesNotSaved"`.
  1868→  1868→
  1869→  1869→**Web clone:** Implement optimistic concurrency using a `version` column (or `last_updated_at` timestamp) and `UPDATE ... WHERE version = $1 RETURNING *`.

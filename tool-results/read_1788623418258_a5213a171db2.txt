    13→## 1. Solution Decomposition (Projects)
    14→
    15→SambaPOS V3 is a **modular composite WPF application** built on top of the Microsoft Patterns & Practices **PRISM** library (event aggregation, region manager, module catalog).     82→### 1.3 Critical architectural finding
    83→
    84→**SambaPOS V3 uses a rich-domain-model, NOT an anemic model.** There are NO standalone `OrderCalculator`, `TaxCalculator`, `TicketTotalCalculator`, `DiscountCalculator` classes. All math is embedded as methods on the entities themselves:
    85→
    86→- `Ticket.GetSum()` / `Ticket.Recalculate()` / `Ticket.CalculateServices()` / `Ticket.CalculateTax()` / `Ticket.GetRemainingAmount()`
    87→- `Order.GetTotal()` / `Order.GetValue()` / `Order.GetTaxablePrice()` / `Order.GetTotalTaxAmount()`
    88→- `TaxValue.GetTax()` / `TaxValue.GetTaxAmount()`
    89→- `Calculation.Update()` — THE unified discount/service/rounding engine (5 calculation types in a single method)
    90→- `AccountTransaction.UpdateAmount()` — handles auto-reversal on negative amounts
    91→
    92→There are also NO domain service interfaces inside `Samba.Domain`. Service interfaces (`ITicketService`, `IAccountService`, `IInventoryService`, etc.) live in `Samba.Services` and `Samba.Presentation.Services`.

   242→## 5. Cross-Cutting Concerns
   243→
   244→### 5.1 Caching strategy
   245→
   246→`Samba.Services/Implementations/CacheService.cs` is the **in-memory cache** that pre-loads all reference data (MenuItems, TaxTemplates, PaymentTypes, CalculationSelectors, ScreenMenus, EntityTypes, AppRules, AppActions, Printers, PrinterTemplates, TicketTypes, Departments, Terminals) at application startup. **The DB is hit once, then everything is read from memory.** Mutations go through DAOs which update both the DB and the cache.
   247→
   248→**Implication for web clone:** For a single-tenant single-terminal replica, an in-memory cache on the backend (or even on the client) is fine. For multi-tenant, the cache must be per-tenant.
   249→
   250→### 5.2 Automation engine
   251→
   252→The automation system (`Samba.Services/Implementations/AutomationModule/`) is a **rule engine**:
   253→
   254→1. **`AppRule`** declares an `EventName` to listen for (e.g. `"TicketCreated"`, `"OrderAdded"`, `"PaymentProcessed"`, `"TicketClosing"`).
   255→2. **`RuleConstraintValue`** predicates are evaluated against the data object (e.g. `{Ticket.TotalAmount} > 100`).
   256→3. **`ActionContainer`** instances run sequentially, each invoking an `AppAction` with parameter values formatted from the data object.
   257→4. **`AppAction.Parameter`** uses `[:PropertyName]` placeholders replaced at runtime.
   258→
   259→Built-in action types (in `Samba.Presentation.Common/ActionProcessors/`): `UpdateOrder`, `UpdateTicketStatus`, `UpdateOrderStatus`, `UpdateOrderGiftState`, `UpdateEntityState`, `CreateTicket`, `CloseTicket`, `DisplayPaymentScreen`, `ExecutePrintBillJob`, `ExecuteKitchenOrdersPrintJob`, `LockTicket`, `UnlockTicket`, `MarkTicketAsClosed`, `PayTicket`, `MoveSelectedOrders`, `AddOrder`, `UpdateEntity`, `SetTicketTag`, `UpdateTicketTag`, `SetTicketState`, `UpdateTicketEntityState`, `UpdateProgramSetting`, `SendEmail`, `ExecuteScript`, `LoopbackValues`, `AskQuestion`, `DisplayTicketList`, `SetCurrentDepartment`, `SetTicketType`, etc.
   260→
   261→### 5.3 Multi-terminal messaging
   262→
   263→`Samba.MessagingServer` is a **TCP hub** (port 8080 by default) that broadcasts `Message` objects between POS terminals. Each `Message` has a string `Topic` (e.g. `"TicketRefreshMessage"`, `"Ping"`, `"EntityRefreshMessage"`) and a payload. Used for cross-terminal ticket table refresh (so terminal A sees terminal B's open tickets).
   264→
   265→**Web clone:** Replace with **WebSocket** (`socket.io` or native `ws`). Same topic-based pub/sub model.
   266→
   267→### 5.4 Concurrency
   268→
   269→`Numerator.LastUpdateTime` is a `byte[]` configured as `IsConcurrencyToken` + `HasColumnType("timestamp")` — EF's optimistic concurrency token. **Every ticket/order number increment is atomic with retry on `DbUpdateConcurrencyException`** (`SettingDao.GetNextNumber` retry loop).
   270→
   271→`TicketDao.CheckConcurrency` (called inside `CloseTicket`) compares the in-memory ticket against a fresh DB-loaded copy: if `TicketEntities` count/IDs, `IsClosed`, `LastPaymentDate`, or `GetSum()` (when `RemainingAmount==0`) differ, the close is rejected with `"TicketPaidLastChangesNotSaved"`.
   272→
   273→**Web clone:** Use Postgres `UPDATE ... WHERE last_updated_at = $1` returning pattern, or Knex `FOR UPDATE` row locks.

   277→## 6. Key Findings & Risks for Web Migration
   278→
   279→### 6.1 Things that translate cleanly
   280→
   281→| Original | Web equivalent | Effort |
   282→|----------|---------------|--------|
   283→| `Samba.Domain` entities (POCO) | TypeScript interfaces + classes | Low — mechanical translation. |
   284→| `OrderBuilder` / `TicketBuilder` (fluent) | Same fluent API in TS | Low. |
   285→| `TaxValue.GetTax` / `Calculation.Update` | Same math, `decimal.js` instead of `decimal` | Low — math is pure. |
   286→| DAO pattern | Repository pattern | Low. |
   287→| `CacheService` | Module-level cache or Redis | Low. |
   288→| PRISM EventAggregator | Custom EventEmitter or RxJS | Low. |
   289→| `FlexButton` control | `<Button>` React component with same CSS | Medium. |
   290→
   291→### 6.2 Things that DO NOT translate directly
   292→
   293→| Original | Issue | Mitigation |
   294→|----------|-------|------------|
   295→| **WPF XAML layout** (Grid with `Width="*"`) | CSS Grid / Flexbox have different sizing semantics | Carefully convert each Grid → CSS Grid with `grid-template-columns: ...fr`. |
   296→| **WPF Resource Dictionaries** (brushes, styles) | No direct equivalent | Map to CSS custom properties + Tailwind theme. |
   297→| **`Microsoft.PointOfService` + RawPrinterHelper** (winspool.Drv P/Invoke) | Browser cannot print raw bytes directly | Use **WebUSB** for ESC/POS, or `window.print()` with a hidden iframe of formatted HTML. |
   298→| **SQL Server CE `.sdf`** | No portable JS driver | **Switch to SQLite (better-sqlite3) or Postgres.** Schema is portable (nvarchar→TEXT, datetime→TIMESTAMP, decimal→NUMERIC). |
   299→| **WPF Storyboards** (animations) | CSS transitions / keyframes | Re-animate `Silver→Gainsboro` etc. as CSS transitions. |
   300→| **`KineticBehaviour.HandleKineticScrolling`** (touch kinetic scroll) | iScroll / native `-webkit-overflow-scrolling: touch` | Use native CSS touch scrolling. |
   301→| **`Microsoft Win32` P/Invoke** (cash drawer, raw print) | Browser sandbox | WebUSB / Web Serial API (Chrome only) or backend-side print service. |
   302→| **PRISM Module Catalog** (dynamic loading) | Webpack code splitting | Lazy-load route components. |
   303→| **`EntityFramework.CodeFirst` conventions** (shadow FK columns like `AccountTransactionType_Id`) | Prisma/Knex require explicit columns | Make all FKs explicit (rename `_Id` → `Id`). |
   304→| **`Stateless` library** (state machines) | XState or custom | Mostly used loosely — could be inline state fields. |
   305→| **`FluentScript`** (custom scripting for automation) | JS `eval` or `vm2` sandbox | Re-implement with `Function` constructor + restricted scope. |

   307→### 6.3 Critical rounding-mode inconsistency to preserve
   308→
   309→SambaPOS V3 uses **two different rounding modes** depending on the code path:
   310→
   311→| Code path | Mode | Source |
   312→|-----------|------|--------|
   313→| `Ticket.CalculateTax` | `decimal.Round(value, 2)` (defaults to `MidpointRounding.ToEven` / banker's rounding) | `Ticket.cs:350` |
   314→| `Ticket.CalculateServices` | `decimal.Round(value, 2)` (banker's) | `Ticket.cs:376` |
   315→| `Ticket.GetTaxTotal` | `decimal.Round(value, 2, MidpointRounding.AwayFromZero)` (schoolbook) | `Ticket.cs:694, 700` |
   316→| `AccountTransaction.UpdateAmount` | `Decimal.Round(Amount, 2, MidpointRounding.AwayFromZero)` | `AccountTransaction.cs:203` |
   317→| `TaxValue.GetTax` (per-line, when `Rounding>0`) | `decimal.Round(..., Rounding, MidpointRounding.AwayFromZero)` | `TaxValue.cs:47` |
   318→| `Calculation.Update` type 4 (rounding) | `decimal.Round(currentSum / Amount, MidpointRounding.AwayFromZero)` | `Calculation.cs:45` |
   319→| `ProductTimerValue.GetPrice` | `decimal.Round(..., LocalSettings.Decimals)` (banker's) | `ProductTimerValue.cs:32` |
   320→
   321→**Web clone MUST preserve this inconsistency** for byte-perfect monetary parity with the original. JavaScript `Math.round` rounds half-up (toward +∞ for `.5`), which matches `AwayFromZero` for positives but NOT for negatives. Use:
   322→
   323→```javascript
   324→const roundBankers = (v, d=2) => { const f = Math.pow(10, d); const n = v * f; return Math.round(n % 1 === 0.5 || n % 1 === -0.5 ? Math.sign(n) * Math.floor(Math.abs(n)) : n) / f; };
   325→const roundAwayFromZero = (v, d=2) => { const f = Math.pow(10, d); return Math.sign(v) * Math.round(Math.abs(v) * f) / f; };
   326→```
   327→
   328→Or just use `decimal.js` with explicit `rounding` modes.

   342→## 7. Glossary
   343→
   344→- **Ticket** = order ticket / table check / receipt.
   345→- **Order** = a single line item on a ticket (NOT a purchase order). Same as "TicketItem" in other POS systems.
   346→- **Calculation** = a discount, service charge, rounding, or manual adjustment applied to a ticket. The `CalculationType` int (0–5) picks the math.
   347→- **OrderTag** = a modifier on an order (e.g. "Extra Cheese", "No Onions"). Belongs to an `OrderTagGroup`.
   348→- **TicketTag** = a free-form or pre-defined tag on a ticket (e.g. "Dine-in", "Takeaway").
   349→- **TicketEntity** = a link between a ticket and an Entity (table, customer, etc.).
   350→- **Entity** = a generic business object — typically a Table or a Customer. Defined by its `EntityType`.
   351→- **AccountTransaction** = a double-entry ledger movement (source → target, debit/credit on each side).
   352→- **WorkPeriod** = a shift / day boundary. Reports are scoped to work periods.
   353→- **Terminal** = a POS terminal registration (used for multi-terminal config scoping).
   354→- **Department** = a context that bundles a TicketType + Warehouse + ScreenMenu + PriceTag.
   355→- **Numerator** = a sequential number generator for ticket/order numbers.
   356→- **ScreenMenu** = the POS product button layout (categories → items → buttons).

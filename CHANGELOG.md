## [Unreleased] — FASE 4 (en progreso)

### Repository reorganization

- **Removed** the `samba-web-clone/` wrapper directory — all content moved to
  repo root via `git mv` (history preserved).
- **Removed** the real `.env` from the repo (was tracked by mistake —
  contained `DATABASE_URL`).
- **Removed** `tool-results/` (24 agent artifact files) and `download/`
  (placeholder).
- **Moved** the 91 KB `worklog.md` to `docs/worklog-history.md` (historical
  forensic analysis).
- **Updated** `.gitignore` to exclude `tool-results/`, `download/`,
  `agent-ctx/`, and reinforce `.env` exclusion with `!.env.example`.
- **Updated** `backend/scripts/run-all-tests.sh`, `smoke-fase3.sh`,
  `debug-fase3.js` to resolve paths relative to the script (no hardcoded
  `/home/z/my-project/sambapos_lba/samba-web-clone/` paths).
- **Updated** `.github/workflows/ci.yml` header to reflect new layout.
- **Renamed** backend package to `sambapos-lba-backend` (v0.4.0).
- **Updated** `/health` and `/version` endpoints to return `service:
  'sambapos-lba'` / `name: 'sambapos-lba'` instead of `samba-pos-web-clone`.

### Visual identity (blue brand)

- **New** `--lba-*` CSS variables in `frontend/css/variables.css`:
  - Blue family: `--lba-blue-50` through `--lba-blue-900` (10 shades).
  - Shell gradient: `--lba-shell-bg` (135deg blue gradient).
  - Surfaces: `--lba-bg-app`, `--lba-bg-panel`, `--lba-bg-sidebar`,
    `--lba-bg-header`, `--lba-bg-hover`, `--lba-bg-selected`.
  - Text: `--lba-fg-default` (navy), `--lba-fg-inverse`, `--lba-fg-on-blue`,
    `--lba-fg-muted`, semantic colors.
  - Accents: `--lba-accent`, `--lba-accent-hover`, `--lba-accent-pressed`.
  - Borders, shadows, radii, animations all blue-tinted.
  - Touch target sizes: 48/56/64/80px (mobile-first).
  - Responsive breakpoints: sm/md/lg/xl/2xl.
- Legacy `--samba-*` variables kept as aliases to maintain backward
  compatibility with existing CSS.

### Mobile-first responsive CSS

- **New** `frontend/css/mobile.css` with:
  - Login card: blue gradient background, large touch targets, blue keypad.
  - Header: sticky, blue, safe-area padding for notch.
  - POS grid: responsive 2 → 6 columns at sm/md/lg/xl breakpoints.
  - Product buttons: 80px min height (large touch target).
  - Command bar: 72px min height, sticky bottom, safe-area.
  - Payment numpad: 64px keys.
  - Modal: responsive max-width, blue-tinted overlay.
  - Toast: bottom-anchored, severity-colored left border.
  - PWA install banner + SW update banner styles.

### PWA (installable)

- **New** `frontend/manifest.webmanifest` — standalone, theme_color
  `#044392`, 4 icons (192/512, any + maskable), 3 shortcuts (POS/KDS/
  Dashboard).
- **New** `frontend/sw.js` — Service Worker with:
  - Precache offline shell (CSS, JS, manifest, vendor).
  - Cache-first for static assets.
  - Network-first for navigations (falls back to cached shell or
    `/offline.html`).
  - Stale-while-revalidate for images.
  - Never caches `/api/*`, `/health`, `/ready`, `/version`, `/socket.io/*`.
  - Versioned with `sambapos-lba-v0.4.0` for cache cleanup.
- **New** `frontend/offline.html` — branded offline page with retry button.
- **New** `frontend/icons/` — 5 PNGs generated by
  `backend/scripts/generate-icons.js` (uses `node-canvas`):
  - `icon-192.png`, `icon-512.png`, `icon-192-maskable.png`,
    `icon-512-maskable.png`, `favicon.png`.
- **Updated** `frontend/index.html`:
  - `<link rel="manifest">`, icon links, apple-touch-icon.
  - `<meta name="theme-color">`, `apple-mobile-web-app-*`,
    `mobile-web-app-capable`.
  - `viewport-fit=cover` for notch support.
  - SW registration script with `updatefound` listener.
- **New** `frontend/js/services/pwa.js` — `window.SambaPWA` API:
  - Captures `beforeinstallprompt` for custom install UI.
  - `promptInstall()` async method.
  - `onInstallState(cb)` subscription.
  - SW update banner ("Nueva versión disponible — Actualizar / Más tarde").

### WebSocket enhancements

- **Heartbeat**: ping every 25s, force-reconnect if no ack in 10s.
- **Browser online/offline detection** via `navigator.onLine` events.
- **Visual indicators**: green (online), orange (reconnecting), red (offline).
- **Toast** "Conexión restablecida" on successful reconnect.

### KDS professional

- **Two-tone chime** (A5 880Hz + E5 660Hz) for new orders — more distinctive
  than single beep.
- **Vibration** on Android via `navigator.vibrate([200,100,200])` —
  toggleable.
- **Browser Notification API** integration — if permission granted, shows
  system notification "Nuevo pedido: #<ticket>" with icon/badge.
- **State filter**: active / ready / served / all — default 'active'.
- **Station tabs with count badge** — shows active orders per station.
- **Sort by Priority desc, then CreatedAt asc** — urgent orders first.
- **Urgent indicator**: card pulses red after 10 min (5 min for priority
  orders); timer pill blinks.
- **Auto-refresh every 30s** as safety net beyond WebSocket events.
- **Track _lastOrderIds** — sound/vibration only fires for genuinely new
  orders, not on first load.
- **`requestNotificationPermission()`** method for app code to call from a
  user gesture.

### Documentation

- **New** `docs/PWA.md` — complete guide: installation, manifest, service
  worker, offline, push, Capacitor future, troubleshooting.
- **New** `docs/PHASE4_REPORT.md` — this report.
- **Updated** `README.md` — badges (244 tests, v0.4.0, PWA), identidad
  visual section, PWA/Android section, roadmap, project structure.

### Bugfixes

- **Fixed** `/version` endpoint — was requiring
  `../../../package.json` (non-existent) — now correctly requires
  `../../package.json` (backend/package.json). Pre-existing bug since before
  reorganization; never caught because `/version` was not in E2E tests.

### Tests

- **Updated** `backend/tests/e2e/ui-isolated.spec.js` B3 test to expect
  `.kds-toolbar` (post-Fase-4 layout) instead of `.kds-stations-bar`
  (legacy class).
- All 217 unit tests + 27 E2E tests PASS post-changes (1 flaky A15 —
  pre-existing race condition).

## [0.4.0] - 2026-09-07 — FASE 1: Seguridad y Limpieza

### Added

- Job de **seguridad en CI** que corre `gitleaks-action@v2` (secret scan con
  `fetch-depth: 0`) + gate `npm audit --audit-level=low` antes de tests.
- **Validación de payload con Zod** en 9 *handlers* críticos (`auth.login` +
  8 endpoints de tickets: `POST /`, `/:id/payments`, `/:id/close`,
  `/:id/note`, `/:id/tags`, `/:id/split`, `/:id/refund`, `/merge`). Nuevo
  módulo `backend/src/api/middleware/schemas.js` con 17 schemas *strict*
  que rechazan claves desconocidas.
- **21 tests de seguridad** (`security-verification.test.js`): 3 de CORS
  *hardening*, 10 de *auth bypass*, 8 de *fuzzing* en login.
- Archivo `.env.example` documentado con todas las variables de la app
  (`PORT`, `NODE_ENV`, `JWT_SECRET`, `JWT_EXPIRES_IN`, `CORS_ORIGIN`,
  `SAMBA_DB_PATH`, `ADMIN_PIN`, `BACKUP_DIR`).
- Middleware `requirePermission()` aplicado a **11 rutas** previamente sin
  RBAC (config: 5, products: 4, tables: 3, printers: 3, kitchen: 2).
- `auditLog()` agregado a `product.create` y `table.changeState`.
- Config `.gitleaks.toml` con *allowlist* para `.env.example`, *test
  secrets*, *bcrypt hashes* y *docs*.
- `data/backups/.gitkeep` para preservar el directorio en git.

### Changed

- **`sqlite3 5.1.7 → 6.0.1`** — resuelve 7 vulnerabilidades (1 crítica en
  `tar` por la cadena `sqlite3 → node-gyp → make-fetch-happen → tar`).
  `npm audit` reporta **0 vulnerabilidades** después del bump.
- **CORS endurecido**: si `NODE_ENV=production` y `CORS_ORIGIN='*'` o vacío,
  el servidor aborta el arranque con `process.exit(1)` y un mensaje claro.
- `data/backups/`, `data/snapshots/`, `backend/tests/e2e/report/` y
  `backend/tests/e2e/results.xml` agregados al `.gitignore`.

### Removed

- `data/samba.db` eliminado del control de versiones (`git rm --cached`).
- `data/backups/samba-backup-*.meta.json` eliminados del control de
  versiones.
- (Limpiado en este release, FASE *repo-cleanup*):
  `backend/test-results/.last-run.json` des-trackeado (artefacto de
  Playwright) y *gitlink* huérfano `source/` (submodule sin `.gitmodules`)
  eliminado del index.

### Tests

- Suite completa: **165/165 PASS** (138 unit + 27 E2E con Chromium 1243).
- Sin regresiones respecto a FASE 0 (144 tests) — los 21 tests nuevos son
  aditivos.

Ver [`docs/PHASE1_REPORT.md`](./docs/PHASE1_REPORT.md) para el detalle
completo.

## [0.3.0] - 2026-09-06 — Versión pública inicial (baseline pre-FASE 0)

### Added

- **POS completo**: tickets, órdenes, pagos, cálculos (con `decimal.js`),
  descuentos, regalos (*gifts*), *voids*, *refunds*, *splits* y *merges*.
- **KDS multi-estación** con *state machine* de órdenes, *routing* por
  estación y propagación de *voids*.
- **Inventario y recetas** con deducción transaccional al cerrar ticket.
- **RBAC con 26 permisos** granulares aplicados vía `requirePermission()`.
- **Impresión real ESC/POS** vía transporte TCP con *retry* y *fallback*.
- **WebSocket con auth JWT**, *rooms* por rol y *resync* tras reconexión.
- **Migraciones Knex** + *seed* transaccional (admin, 19 reglas de
  cálculo, 4 *payment types*, 3 *printers*, etc.).
- **Frontend Vanilla JS + Web Components**: Login, Dashboard (mapa de
  mesas), POS, Payment Editor, KDS.
- **Docker multi-stage** + `docker-compose.yml` con healthcheck.
- **CI en GitHub Actions**: install → lint → migrate → tests → docker build.
- **144 tests passing**: 47 integration + 49 KDS + 13 inventory + 8
  concurrency + 27 E2E (Playwright).

### Known issues (resueltos en 0.4.0)

- `data/samba.db` commiteado en el repo (corregido en FASE 1.2).
- `sqlite3@5.1.7` con 7 vulnerabilidades (corregido en FASE 1.3).
- CORS aceptando `*` en producción (corregido en FASE 1.5).
- 11 rutas sin `requirePermission()` (corregido en FASE 1.6).
- 9 *handlers* sin validación de schema (corregido en FASE 1.7).
- Sin secret scan automatizado (corregido en FASE 1.8).

Ver [`docs/BASELINE_REPORT.md`](./docs/BASELINE_REPORT.md) para el detalle
completo del baseline.
